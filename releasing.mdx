title: "Release operations"

---

The current release is **v0.2.2**. Client releases and relay/STUN deployment are separate operations. Maintainers need repository and deployment access; users download from the Neutrino server.

<Steps>
<Step title="Choose and verify">
Use semantic versioning and document incompatible wire changes. Run the checks from `RELEASING.md`:
```bash
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```
Contribution rules additionally require the all-features Clippy check before code review approval.
</Step>
<Step title="Bump versions together">
For example, prepare the next minor version:
```bash
sh scripts/bump-version.sh 0.3.0
```
The script updates workspace crates, desktop/Tauri configuration, and `Cargo.lock`. Review all changes.
</Step>
<Step title="Commit, tag, and push">
```bash
git commit -am "chore: release v0.3.0"
git tag v0.3.0
git push
git push origin v0.3.0
```
The tag push triggers the GitHub Actions `release` workflow, which rejects a tag that does not match the Cargo version.
</Step>
<Step title="Verify deployment and smoke test">
The workflow builds `neutrino` and `neutrinod` for the five [targets](/installation), generates `SHA256SUMS`, uploads to `/var/www/neutrino-dl/v0.3.0/`, refreshes both installers, then updates `latest.txt`.

Check the Actions run, reinstall on two machines, check versions, and transfer a folder. Confirm contents and verified completion on both sides. Test forced relay as well as direct connectivity when validating network changes.
</Step>
</Steps>

## Rollback

Old version directories remain available. An authorized server operator can run this on the download server:

```bash
printf '%s\n' v0.2.2 > /var/www/neutrino-dl/latest.txt
```

Existing installs do not downgrade automatically. Users rerun the installer or pin `NEUTRINO_VERSION=v0.2.2`. To republish an existing tag after workflow repairs, select **Actions → release → Run workflow** with that tag.

## Deployment access

Actions uses `DEPLOY_SSH_KEY`, `DEPLOY_HOST`, and `DEPLOY_KNOWN_HOSTS`. The upload account is restricted to `/var/www/neutrino-dl`. Keep secrets in Actions secrets and pin the SSH host key.

See the source checkout's `RELEASING.md` and `deploy/SERVER.md` for maintainer procedures. Relay changes must preserve compatibility with clients in the field; see [self-hosting](/self-hosting/relay).
