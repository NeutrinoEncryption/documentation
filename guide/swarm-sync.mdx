## Overview

Neutrino's Continuous Swarm Sync enables decentralized multi-way folder synchronization across arbitrary peer meshes. Unlike centralized services that store file trees on remote cloud servers, Swarm Sync keeps all state, Merkle-DAG indices, and chunk caches on local machines.

```mermaid

    NodeA["Peer A (Workstation)"]
    NodeB["Peer B (Laptop)"]

    NodeA <-->|QUIC Swarm Control Stream (Merkle Tree Diff)| NodeB
    NodeB <-->|QUIC Swarm Control Stream| NodeC
    NodeA <-->|Direct P2P Chunk Beam| NodeC
```

## Setting Up Swarm Sync

### 1. Creating a Share Space

On the originating machine, share a local directory:

```bash
neutrino sync share ~/Projects/research-vault "Research Vault"
```

The daemon initializes an embedded SQLite database (`PRAGMA journal_mode=WAL`), calculates FastCDC chunk boundaries for existing files, and prints a share invitation code:

```text
  Sync Space Created: "Research Vault"
  Space ID: 4f1a-8b92-e034
  Invite:   swarm::7a8b9c...f0e1
```

### 2. Joining a Share Space

On secondary workstations or team members' machines, join using the invite code:

```bash
neutrino sync join swarm::7a8b9c...f0e1 ~/Mirrors/research-vault
```

The joining node pulls the directory manifest, executes anti-entropy Merkle search tree diffing against all online swarm peers holding valid replicas, and concurrently downloads missing chunks.

## Managing Swarm Shares

```bash
# Display real-time status of all active sync spaces
neutrino sync status

# List all tracked sync shares and their storage locations
neutrino sync list

# Force an immediate filesystem scan for modified files
neutrino sync scan [SHARE_ID]
```

## Filesystem Watcher & Debounce

The daemon monitors local sync directories using `notify-debouncer-mini`:
* **Debounce Window**: Rapid sequential writes (e.g. IDE auto-save or git checkout) are debounced across a 300ms window before chunking is triggered.
* **`.neutrinoignore` Support**: Place a `.neutrinoignore` file in the sync root to exclude paths:
  ```gitignore
  .git/
  node_modules/
  target/
  *.tmp
  .DS_Store
  ```

## Conflict Resolution: Last-Write-Wins (LWW)

When two or more peers edit the same file concurrently while partitioned, Neutrino applies deterministic Lamport logical clocks:

1. The mutation with the **highest Lamport timestamp** wins the canonical path.
2. In the event of an exact timestamp tie, the higher lexicographical actor public key breaks the tie deterministically.
3. The losing replica is **never deleted or overwritten**. Instead, it is automatically branched to:
   ```text
   document.conflict-1718042918-a4f2e8.md
   ```
4. The daemon emits a `sync.conflict` event over IPC, alerting the client and UI.
